# Aula 08/09/2026 — Separação de Estilos e Lógica (CP3)

Revisão da prática da **Aula 24/03/2026** (Organização Avançada: Separação de
Estilos e Lógica) aplicada ao estado atual do projeto, que cresceu ao longo do
semestre (login, perfis, PA/IoT, agenda do médico etc.).

## Contexto

| Aula     | O que fizemos                                        |
|----------|------------------------------------------------------|
| 03/03    | MVP simples do projeto                               |
| 10/03    | TypeScript, types e interfaces                       |
| 17/03    | Componentização (ConsultaCard)                       |
| 24/03    | Separação de estilos + `screens/` + `App.tsx` limpo  |
| Semestre | Features: auth, admin, médico, PA, emergência…       |

**Problema:** as telas novas voltaram a misturar lógica + JSX + `StyleSheet` no
mesmo arquivo (200–500+ linhas), dificultando leitura, revisão e manutenção.

**Missão:** extrair os estilos de todas as telas e componentes para
`src/styles/`, deixar cada arquivo com uma responsabilidade e manter o app
funcionando — sem features novas e sem mudar o layout.

## Regra de ouro

| Camada             | Onde fica                         | Contém                               |
|--------------------|-----------------------------------|--------------------------------------|
| Tipos / Interfaces | `src/types/`, `src/interfaces/`   | Contratos de dados                   |
| Lógica / JSX       | `src/screens/`, `src/components/` | Estado, handlers, UI                 |
| Estilos            | `src/styles/`                     | Apenas `StyleSheet.create`           |
| Entrada            | `App.tsx`                         | Inicialização (providers, navegação) |

## Método (por arquivo)

1. Localizar o bloco `const styles = StyleSheet.create({ ... })` no final do arquivo.
2. Criar `src/styles/<nome>.styles.ts` (camelCase + sufixo `.styles.ts`).
3. Mover o `StyleSheet.create` para o novo arquivo com `export const styles`.
4. No componente/tela: remover `StyleSheet` do import do `react-native` e
   adicionar `import { styles } from '../styles/<nome>.styles'`.
5. Testar a tela no Expo e seguir para o próximo arquivo.

Os valores visuais (cores, espaçamentos, fontes) **não mudam** — o objetivo é
mover, não redesenhar.

## Modelo da aula — `Input`

`src/styles/input.styles.ts`:

```ts
import { StyleSheet } from 'react-native';

/**
 * Estilos do componente Input.
 * Separados da lógica para facilitar manutenção e reuso.
 */
export const styles = StyleSheet.create({
  container: { marginBottom: 16 },
  label: { fontSize: 14, fontWeight: '600', color: '#333', marginBottom: 6 },
  input: {
    backgroundColor: '#fff',
    borderWidth: 1,
    borderColor: '#ddd',
    borderRadius: 8,
    padding: 12,
    fontSize: 16,
    color: '#333',
  },
  inputError: { borderColor: '#f44336' },
  errorText: { color: '#f44336', fontSize: 12, marginTop: 4 },
});
```

`src/components/Input.tsx` (só lógica + JSX):

```tsx
import React from 'react';
import { Text, TextInput, TextInputProps, View } from 'react-native';
import { styles } from '../styles/input.styles';

type InputProps = TextInputProps & {
  label: string;
  error?: string;
};

export default function Input({ label, error, ...props }: InputProps) {
  return (
    <View style={styles.container}>
      <Text style={styles.label}>{label}</Text>
      <TextInput
        style={[styles.input, error ? styles.inputError : null]}
        placeholderTextColor="#999"
        {...props}
      />
      {error ? <Text style={styles.errorText}>{error}</Text> : null}
    </View>
  );
}
```

> Diferença em relação ao modelo do enunciado: `error && ...` foi trocado por
> ternário. Com `strict: true` o `error && styles.inputError` não compila
> (`""` não é um estilo válido) e, em runtime, `error = ""` renderizaria uma
> string solta fora de `<Text>` ("Text strings must be rendered within a
> <Text> component").

`src/styles/index.ts` reúne todos os estilos como barrel opcional
(`inputStyles`, `loginStyles`, `navigationStyles`, …).

1. `npm start` (ou `npx expo start`).
2. Entrar como paciente, médico e admin (credenciais de teste no README).
3. Abrir: Home, Agenda, Detalhes, Nova Consulta, Pressão Arterial, Cadastro, Admin.
4. Conferir que o layout está igual ao de antes da refatoração.
5. Nenhum erro vermelho de import / `styles is not defined`.
